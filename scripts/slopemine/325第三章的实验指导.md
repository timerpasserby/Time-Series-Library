## 五、接下来我怎么一步步带你做实验

下面开始第二个任务。我按“从数据到结果”的真实实验流程带你，不空讲。

------

## 第 0 步：先把实验目标固定住

你这章对应的实验，不是简单证明“模型预测准”。
你要同时回答 4 个问题：

1. **预测性能是否提升？**
2. **多源信息是否真的有效？**
3. **物理先验和事件驱动机制是否真的必要？**
4. **模型是否有工程解释性和鲁棒性？**

所以你的实验章建议分成：

- 数据集与预处理
- 实验设置
- 主实验：与基线比较
- 消融实验
- 参数敏感性实验
- 可解释性与案例分析
- 小结

------

## 第 1 步：先整理你的原始数据表

你现在先不要急着训练模型。
先把所有数据整理成 3 张主表。

### 1.1 监测点静态信息表 `point_meta.csv`

每一行一个监测点，至少包含：

- `point_id`
- `x, y, z`
- `u, v`（二维投影坐标）
- `zone_id`（工程分区）
- `grid_id` 或 `patch_id`
- 是否有效点 `is_valid`

这张表的作用是：

- 后面做空间分块；
- 构造 prior graph；
- 画可视化图。

### 1.2 位移时序表 `disp_series.csv`

长表或宽表都行，但我建议长表更稳：

- `timestamp`
- `point_id`
- `disp`
- `vel`（如果已有）
- `acc`（如果已有）
- 其他内部变量

你必须先确认时间粒度是否统一，比如都是小时级。
如果不是，先统一到同一采样间隔。

### 1.3 外部事件表

分成两张：

#### 气象表 `weather.csv`

- `timestamp`
- `rainfall`
- `temperature`
- `humidity`

#### 爆破表 `blast.csv`

- `blast_id`
- `timestamp`
- `bx, by, bz` 或投影坐标
- `charge` 或 `intensity`

如果你现在还没有整理成这三张表，后面所有模型设计都没法落地。

------

## 第 2 步：先做数据质量诊断，不要直接清洗

你第一轮不是清洗，而是先“看数据”。

你要输出 6 个统计：

1. 监测点总数、有效点数
2. 每个点缺失率分布
3. 每个点异常值比例
4. 位移/速度/加速度分布
5. 爆破事件时间分布
6. 降雨时间分布与强度分布

你要先回答几个问题：

- 缺失最严重的是哪些区域？
- 爆破是否集中在某些时段？
- 位移突增是否和爆破/降雨在时间上有重叠？
- 数据是否存在明显的静稳期和活跃期？

这一步的结果会决定你后面的实验设计。
因为如果你的数据根本没有明显爆破响应，那“事件驱动路由”很难证明有效。

------

## 第 3 步：做预处理，但每一步都要可复现

你的预处理建议按这个顺序：

### 3.1 时间对齐

把位移、气象、爆破都对齐到统一时间轴，比如 1 小时。

对于爆破，原始是离散事件，不需要补成普通时序列，先保留事件表，后面单独转成爆破影响矩阵。

### 3.2 缺失值处理

建议分层处理：

- 连续缺失太长的点，直接剔除；
- 短缺失，用线性插值；
- 局部极短缺口可用前向/邻近填补。

你要把“剔除阈值”写死，例如：

- 连续缺失超过 24 小时剔除
- 总缺失率超过 20% 剔除

### 3.3 异常值处理

你文中提了 LOF 和滑动中位数。
实验里建议你实际做成：

- 先用滑动 z-score 或 Hampel 过滤极值
- 再做平滑

因为 LOF 在超大规模时序点数据上计算代价和参数敏感性都不小，除非你已经实现得很顺。

### 3.4 归一化

必须注意：

- 位移类特征：建议按训练集统计量做标准化；
- 气象特征：可做 Min-Max 或 z-score；
- 爆破强度：建议 log 变换后归一化。

而且**只能用训练集拟合归一化参数**，不能全数据一起算。

------

## 第 4 步：构造监督学习样本

你现在的模型是滑窗预测，所以必须先把数据切成样本。

对于每个样本，你要明确：

- 历史窗口长度 `L`
- 预测长度 `T`
- 滑动步长 `S`

例如：

- 用过去 24 小时预测未来 6 小时，
- 或过去 48 小时预测未来 12 小时。

你先做一个基线版本，我建议：

- `L = 24`
- `T = 6`
- `S = 1`

原因很简单：先跑通。

每个样本应包含：

- `X`: 历史内部监测特征
- `W`: 同期气象窗口
- `B`: 同期爆破事件集合或转化后的爆破矩阵
- `Y`: 未来位移目标

------

## 第 5 步：先做最朴素的爆破特征，不要一上来就全公式

虽然你论文方法里是空间衰减 + 时间衰减，但在真实实验上我建议你分三层做。

### 5.1 爆破特征 V1：最简单基线

对每个时间步做：

- 当前小时是否有爆破
- 当前小时爆破总强度

这是给后面做对比用的。

### 5.2 爆破特征 V2：时间滞后版

加入最近若干小时累计爆破强度，例如：

- 最近 1h
- 最近 6h
- 最近 12h

### 5.3 爆破特征 V3：你的论文版

对每个点构造：
[
e_{i,t}=\sum_{k:t_k\le t}Q_k\exp(-d_{ik}^2/2\sigma^2)\exp(-\gamma(t-t_k))
]
这才是正式模型输入。

这样做的好处是，你后面能证明：

> 不是“只要加爆破就有用”，而是“具有空间衰减和时间滞后的结构化爆破建模更有效”。

这个实验很关键。

------

## 第 6 步：空间分块先做可视化核验

在训练前，你必须先把以下图画出来：

1. 投影后的监测点分布图
2. 工程分区图
3. 规则网格/patch 划分图
4. 每个 patch 的点数分布图
5. 有效 patch 数量统计

这一步不是形式主义。
因为你的 patch 设计如果不合理，后面所有模型都白做。

你要检查：

- patch 是否跨越明显地质边界；
- patch 点数是否严重失衡；
- 是否有大量单点 patch；
- 活跃点是不是被摊薄到很多 patch 里。

如果 patch 划得不好，模型学不到东西。

------

## 第 7 步：数据集划分必须按时间切，绝不能随机切

你的任务是时间序列预测，所以必须：

- 训练集：前 70%
- 验证集：中间 10%–15%
- 测试集：后 15%–20%

不能随机 shuffle。
否则会数据泄漏。

如果你数据跨多个明显工况阶段，我建议额外做：

- **时段外泛化测试**
- 比如用平稳期训练，活跃期测试；或跨季节测试

这样更能体现工程价值。

------

## 第 8 步：先跑一组基础基线，不要急着上大模型

你第一轮实验必须有这些基线：

### 传统基线

- HA / Last Value
- Linear Regression
- XGBoost 或 LightGBM

### 深度时序基线

- LSTM
- GRU
- TCN

### 时空/多变量基线

- Transformer 类
- STGCN / GraphWaveNet 一类
- 原始 TimeFilter

其中最重要的是 **原始 TimeFilter**，因为你的方法是基于它改造的。
如果你比一堆无关模型强，但比不过原始 TimeFilter，你的方法主张就站不住。

------

## 第 9 步：评价指标要分三类

不要只报 RMSE。

### 9.1 数值精度指标

- MAE
- RMSE
- MAPE（如果位移接近 0 很多，可以慎用）
- R²

### 9.2 趋势一致性指标

你任务强调“趋势预测”，所以建议加：

- 趋势方向准确率
- Pearson/Spearman 相关系数

### 9.3 事件敏感性指标

针对爆破/降雨触发时段，单独统计：

- 事件窗口内 MAE/RMSE
- 峰值响应误差
- 突变时段方向准确率

这一类非常重要。
因为你的事件驱动路由不是为了提升所有时段一点点平均精度，而是为了在**异常工况下更稳更敏感**。

------

## 第 10 步：消融实验必须按“主线”设计

这是最关键的一步。
你的消融不要乱拆，要围绕主创新来。

我建议至少做这 7 组：

1. **TimeFilter**
   原始基线
2. **TimeFilter + Multi-source**
   只加爆破和气象，不加后面机制
3. **+ Patch Token**
   加时空分块和点级解码
4. **+ PGGC**
   加物理先验图
5. **+ EDDR**
   加事件驱动路由
6. **+ PIR**
   加物理一致性损失
7. **MS-TimeFilter**
   完整模型

这样你就能清楚回答：

- 哪一步贡献最大，
- 哪一步是辅助增益，
- 是否存在模块互补。

------

## 第 11 步：做替代实验，不然你的设计说服力不够

你有几处是“设计选择”，需要替代实验。

### 11.1 爆破特征替代

比较：

- 二值爆破标签
- 仅时间累计强度
- 你的空间+时间衰减建模

### 11.2 图构建替代

比较：

- 纯 learned graph
- 纯 prior graph
- prior + learned 融合

### 11.3 路由替代

比较：

- 原始 MoE 路由
- 不加爆破驱动的路由
- 加爆破驱动的 EDDR

### 11.4 物理损失替代

比较：

- 无物理约束
- 只加速度一致性
- 速度+加速度一致性

这组实验会让你的方法从“看起来合理”变成“有证据支持”。

------

## 第 12 步：参数敏感性只挑最关键的 5 个

别把所有参数都扫一遍，太乱。
只做最关键的：

- 时间窗口长度 `L`
- 预测步长 `T`
- patch 网格尺度 / patch 容量
- 爆破空间衰减参数 `σ`
- 物理损失权重 `β`

如果还有精力，再补：

- 专家数 `K_exp`
- 图先验融合系数 `γ`

------

## 第 13 步：可解释性分析是你的加分项

你这模型最适合做三类可解释性展示：

### 13.1 图结构可视化

展示某一时段 patch 之间的连接：

- 纯 learned graph 容易乱连
- PGGC 更符合工程相邻性

### 13.2 路由权重可视化

在爆破发生前后，展示专家权重变化。
如果事件驱动路由真的有效，应该能看到爆破时段某类专家权重明显升高。

### 13.3 典型案例曲线

选几个点：

- 平稳点
- 缓慢变形点
- 爆破敏感点

画真实值、原始 TimeFilter、你的模型的对比曲线。
这比只放总表更有说服力。

------

## 第 14 步：你现在最先该做什么

如果你现在就开始干，我建议顺序是：

**今天先完成这 4 件事：**

1. 整理三张主表：`point_meta / disp_series / weather / blast`

3. 统计缺失率、异常率、爆破事件分布
4. 把工程分区和二维投影画出来

这四件做完，你的实验就真正开始了。
